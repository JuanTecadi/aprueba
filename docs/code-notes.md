# Code notes

How `index.html` and the tests are built **now**: structure, tokens, views, helpers and the database in short. Read this before changing the app. Moved here from the project document *Prototype – how to continue* on 11 November 2026 (notes about the code live next to the code). The rules for interface work, how to run the tests and how to deploy stay in that document; the history of the code is in the project document *Aprueba – History*.

Keep this file current: when a change adds, renames or removes a view, helper, class family or token, update the matching line here in the same commit.


**Page and shell**

- **Structure:** `<svg class="land">` (the grade landscape: two dune paths, fixed behind everything, fills `--l1` and `--l2`), then `.shell` with `nav.rail#rail` and `.stage` (`header.info#top` and `main#app`). `#app` has `lang="es"` so long Tema names break at syllables on phones.
- **Tokens** (block «v0.3 foundations», after the old base rules so it wins): grade 5to `--g-bg` #1B2A55, `--g-rail` #121D3D, `--g-land1` #22336A, `--g-land2` #2A3D78, `--g-pill` #2E4A9A (only 5to is built). Deep Materia tones `--cie-d|r|l1|l2` (#0A4E70, #083B55, #0C5A80, #106690), `--len-*` (#811B4E, #61153B, #931F5A, #A62365), `--mat-*` (#23267A, #1A1C5B, #292C8F, #2E32A3), `--soc-*` (#763600, #5A2900, #883D00, #9A4500); `--mat-tile` #5559D6. Each Materia also has `--cie` (fill), `--cie-t` (text), `--cie-s` (soft tint), and the same for `--len`, `--mat`, `--soc`; `--mc` is the fill and `--mt` the text tone in use. The surface in use is `--bg`, `--rail-bg`, `--l1`, `--l2`.
- **Surfaces, set by `render()`:** reading screens (`pregunta`, `respuestas`) get `body.s-read` with the Materia soft tint and no landscape; Materia screens (`materia`, `intro` and `resultado` of one Materia or Tema, `progreso` of one Materia) get the deep Materia tone through `MDEEP(id)`; everything else stays on the grade colour. `body.tinted` gives `--sft`. `login` gets `body.s-login`; `pregunta` gets `body.v-preg`.
- **`render()`:** draws the view first (so it can call `head()`), then `renderRail()`, then `renderTop()`; sets `prevView` after drawing. Sends a visitor without `uid` to `login`, an account without a nickname to `apodo`, and `resultado` / `respuestas` without a result, `pregunta` without a Prueba and `intro` without a pick to `home`. `VIEWS` includes `ayuda` and `respuestas`.
- **Rail (`renderRail()`):** `RAIL` = Pruebas (`home`, `#i-PRU`), Progreso (`progreso`, `#i-PRO`), Tabla (`tabla`, `#i-TAB`), Ayuda (`ayuda`, `#i-AYU`), and the gear (`config`, `#i-CFG`, class `cfg`, at the bottom). `railOf(view)` maps `materia`, `intro`, `resultado`, `respuestas` to Pruebas. Selected item: `.ri.on` (yellow) and `aria-current="page"`. Buttons call `leaveTo(view)` (during a Prueba it sets `P.quit = true` and `P.quitTo = view` and shows the «Salir» confirmation). Hidden (and `body.has-rail` removed) without a nickname and on `login`, `apodo`, `pregunta`. The badge `img/aprueba-icon.svg` at the top. Phones (< 600 px): a bottom bar (64 px plus the safe area; badge hidden); the stage has 16 px sides and room at the bottom.
- **Information area (`renderTop()`):** `head({ back: [id, textKey, action], icon, title, pill, extra })`. The third item of `back` is the action, bound by `renderTop()`. `icon` and `title` are wrapped together in `.tt`; `extra` is inserted after the pill (nothing uses it now). Right: `.tools` with `#snd` and `#ptsbtn` (podium, `puntosTotales`; opens the *Tabla*). **Phones:** `.info` wraps and `.ttl` is `display: contents`, so `.tools` stays on the first line and, after a back link, `.tt` takes the full second line; the grade pill is hidden. Reading screens: the sound and points buttons are white; the rail (on «Mis respuestas») is a light shade of the tint with ink #47506A. On `pregunta`, `body.v-preg .info { width: 780px; max-width: 100%; margin: 0 auto }` aligns «‹ Salir» and the points chip with the card.
- **Buttons:** `.b` (56 px pill, min-width 200 px, 18 px bold) with `.b-pri` (yellow) or `.b-sec` (white, 1.5 px #C9CFDB outline; `.b-sec.on-dark` = outline on dark, 48 px, 56 px touch area); `.b.wide` (full width); `.b-link` (text link, 56 px touch area); `.actions` (bottom right; full width and stacked on phones); `.b-back` (compact «‹ Volver», 44 px, touch area 56 px); `.seg` (the one segmented control; `aria-pressed="true"` = selected; `display: inline-flex`, `white-space: nowrap`).
- **Shared pieces:** `.flabel`, `.field` (56 px, 1.5 px #C9CFDB outline, radius 12), `.note`, `.error` and `.okmsg` (hidden when empty), `.check` (the tick box). **One switch style:** `toggle(id, on, label)` draws `button.tg` (`role="switch"`, `aria-checked`; 56 × 32, green #1F9D55 when on; touch area enlarged with `::before`). `tablaDefault()` is true when `tablaPorDefecto` is activado. Page content uses `.page` (white text on the dark surface) and `.pcard2` (white card, 620 px).
- **Icons:** symbols `#i-CIE`, `#i-LEN`, `#i-MAT`, `#i-SOC`, `#i-PRU`, `#i-PRO`, `#i-TAB`, `#i-AYU`, `#i-CFG`, the 47 Tema icons `#i-CIE-T01` … `#i-CIE-T12`, `#i-LEN-T01` … `#i-LEN-T12`, `#i-MAT-T01` … `#i-MAT-T12`, `#i-SOC-T01` … `#i-SOC-T11` (just before `#i-ALL`), and `#i-ALL`, the four-colour “+” (fixed fills; `micon('ALL')` adds the class `todo`). **The symbols in `index.html` are the source of the icons** (the drawing script was a one-off). `micon(id)` draws a Materia icon; `temaIcon(mid, tid)` returns the Tema icon or `null` (then the screen shows the number, or the Materia icon in the question band).
- **Logo:** `logo(dark = true)` returns one image (`-on-dark` by default; `logo(false)` for light backgrounds).

**Points, accounts, saving, sound**

- **Points:** `savedPoints()` adds the saved Pruebas; `livePoints()` adds the answers of the Prueba on screen (only while the view is `pregunta`); `totalPoints()` is both. The option handler compares the total before and after and sets `state.ptsAnim = { from, to }`; `renderTop()` then runs `countUp()`: class `.pop` (yellow, scale) for 0.45 s and the number counting up over 0.4 s (no count-up with reduced motion). An abandoned Prueba returns the chip to the saved total.
- **Accounts:** the Supabase client is loaded from `https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2.49.4/dist/umd/supabase.js` (pinned); if it cannot load, login shows `errorConexion`. `SUPABASE_URL`, `SUPABASE_KEY` at the top of the accounts block; `MIN_PASS` 6 (Supabase's default). State: `state.uid`, `state.email`, `state.user` (the nickname), `state.enTabla`. Helpers: `client()`, `loadProfile()` (reads `nickname` and `leaderboard`), `enterAs()`, `saveNickname()` (returns the text key of the message, or null; a taken nickname comes back as error `23505` → `apodoOcupado`), `signOut()`. Sign-up sends `adult_confirmed: true` in the sign-up metadata, which the database trigger stores. `start()` loads the files, then restores a session saved on the device (`auth.getSession()`).
- **Saving:** after login `enterAs()` calls `loadHistory()`: the student's own `pruebas` with their `answers` (one request, ordered by `finished_at`) become the records the maps and points use (`userData().pruebas`, each with `respuestas: [{ id, correcta, opcion, ms }]`); own `ratings` fill `votes`; then `sendPending()`. At the end of a Prueba `finish()` gives the record an id (`crypto.randomUUID()`), each answer the code of the option chosen (`q.codes[x.chosen]`) and its time stamp (`it.answeredAt`), puts the record and the `save_prueba` payload in the waiting list on the device (`aprueba.v02.pendientes.<account id>`), and `sendPending()` sends the list oldest first and removes each one saved. The result screen never waits for the network. `save_prueba` ignores a second save of the same id. **Thumbs:** `vote()` upserts `{ student_id, question_id, valor }` or deletes the row when tapped again; with no connection the thumb shows but is not saved (no retry). On iPad and iPhone, the app opened from its home-screen icon has its own storage, so a Prueba waiting in Safari is sent only from Safari.
- **Sound:** generated with the Web Audio API, no audio files. `SFX` holds the three sounds (`correcta` = “Marimba”, `incorrecta` = “Toc suave”, `clic` = “Tic”); `sfx(name)` plays one if sound is on, a student is logged in and the browser supports it. Master volume `0.6 × volumenSonido²`. On/off is stored on the device under `aprueba.v01.sonido`; until the student chooses, `sonidoInicial` decides. The answer handler plays `correcta` or `incorrecta`; a capture-phase click listener plays `clic` for every button except the options (`.qo`) and `#snd`; the tap-anywhere listener plays `clic` before moving on; turning sound back on plays one `clic`. No sound on the login screen.
- **Rotating lines:** `say(key)` picks one line at random from a group in `textos.json`, never the same index as the last one shown for that group (memory only, per page load); used for `resumen.*` only.
- **Unused helpers:** a few v0.2 functions nothing calls (for example `mbadge()`, `bigCoach()`) are still in the JavaScript; harmless (section 6).

**The database** (full description in *Aprueba – Data Structure*, section 10; code in `supabase/schema.sql`)

- **Tables:** `students` (one per account: nickname, leaderboard opt-in, `adult_confirmed`), `pruebas` (one per finished Prueba), `answers` (one per question answered, with the option chosen as K, D1, D2 or D3), `ratings` (one thumb per student and question).
- **Sign-up:** a `students` row is created automatically; the app passes the parent's tick box as `adult_confirmed`. The column default of `leaderboard` is `false`; the app saves the nickname screen's switch with the nickname.
- **Functions:** `save_prueba(p)` saves the Prueba and all its answers together or not at all, and ignores a second save with the same id; `tabla_posiciones(...)` returns only rank, nickname, points and whether the row is the caller's, for students who opted in.
- **Access rules:** each student reads and writes only their own rows; saved Pruebas and answers cannot be edited or deleted from the app; nothing can be read without signing in. The board function is the one designed exception.
- **Backstage:** four views in the schema `backstage` (`por_tester`, `por_pregunta`, `votos`, `resumen`), visible only from the Supabase dashboard (Table Editor → schema `backstage`; Export to CSV) or read by Claude with the connector. No admin page for now.
- **Login settings in Supabase:** email and password only; public sign-ups open; **Confirm email off** for the test.
- **Security advisor:** two warnings, both known: leaked password protection off (believed to be a paid-plan feature, not verified; check before going public) and `tabla_posiciones` (security definer, callable by signed-in users; intended; review before going public).
